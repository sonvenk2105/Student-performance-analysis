# Student Performance Analysis

A modular Flask application for student marks entry, validated academic analysis, history, PDF reports, administrator grading rules, and read-only Power BI data views. The application uses PostgreSQL in deployment, with SQLite available for quick local checks. No student results are fabricated. ML prediction is intentionally not shown until a suitable dataset has been evaluated.

## Requirements

Python 3.11+, PostgreSQL 14+, and Git. On Windows, open this folder in VS Code and use its PowerShell terminal.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Set a long random `SECRET_KEY` and a PostgreSQL `DATABASE_URL` in `.env`. Never commit `.env`. Create a local role and database in PostgreSQL (choose your own password):

```sql
CREATE USER student_app WITH PASSWORD 'use-a-long-local-password';
CREATE DATABASE student_performance OWNER student_app;
```

Then apply migrations:

```powershell
$env:FLASK_APP = "wsgi.py"
flask db upgrade
flask init-grading
flask run
```

Commit the generated `migrations/` directory. The first two migration commands are run once; later model changes use `flask db migrate -m "description"` and `flask db upgrade`. Use transactions and review autogenerated migrations before applying them.

## Administrator setup

There is no public admin registration. Set these environment values temporarily in the deployment shell or local terminal, then run `flask create-admin`: `ADMIN_EMAIL`, `ADMIN_NAME`, and `ADMIN_PASSWORD` (at least 14 characters). Clear the temporary password variable afterward. The command creates an account with a hashed password and never prints the password.

## Optional prediction model

The normal install excludes scikit-learn. To enable the optional offline evaluation command, install `requirements-ml.txt`, then run `flask evaluate-prediction-model` against a database with historical assessments. The command requires 20 students and 100 valid training sequences, evaluates on held-out student groups, compares to a mean baseline, stores metrics, and saves a private model artifact only when the MAE gate passes. Student estimates are served only on the separate Future Estimate page; ordinary dashboard and assessment requests do not import scikit-learn. With insufficient data or a failed gate, the page shows no estimate.

## Student features

- Student registration and password-hashed login, CSRF-protected forms, role checks, account ownership checks, and secure session cookie settings.
- Login failures are throttled at 10 per 15 minutes per HMAC-hashed email/IP identity; raw IP and email are not stored in the throttle table. Remove old counters with `flask cleanup-login-attempts`.
- Administrators can add/remove course/semester subject suggestions with maximum and passing marks. Students can select a matching subject to prefill those marks; assessment history keeps its saved values.
- Marks entry supports varied maximum and passing marks. Calculations are shared in `app/analysis.py`, use weighted percentage, configurable grade ranges, subject-level pass checks, and versioned rule snapshots.
- Students can modify or delete only their own saved assessments from performance history. Edits recalculate the same record with its saved grading-rule snapshot; a request key and database uniqueness constraint reduce accidental duplicate submissions.
- The top-right account popup shows the student's name and ID, offers a secure password change, and supports permanent account deletion after password confirmation. Passwords remain one-way hashed and are never displayed.
- PDF report and marksheet import. XLS/XLSX spreadsheets and selectable-text PDFs are read automatically; JPG/PNG OCR works when Tesseract is installed and configured with `TESSERACT_CMD`. Imports accept up to 10 MB and 40 subjects. The original file is discarded after reading; extracted rows are staged in a private, short-lived draft and must be reviewed before analysis. Run `flask cleanup-uploads --days 30` regularly to remove abandoned drafts (after one day) and any legacy uploads.
- Responsive pages; Chart.js is loaded only on result pages. Trend comparisons are not inferred across incomparable subjects or assessment structures.

## Migrations and health

`Flask-Migrate` manages schema history. The initial migration is committed in `migrations/versions/0001_initial_schema.py`; on a clean database run `flask db upgrade`. The health endpoint is `GET /health`; it returns 503 if the database cannot be reached. Configure Render's health check path to `/health`.

## Tests

```powershell
pytest
```

Tests cover weighted calculations, grade boundaries/configuration, validation, authentication, ownership, and report access. They use an isolated in-memory database. For deployment verification, also test migrations and concurrent requests against a staging PostgreSQL database; response-time capacity depends on the chosen Render resources and workload.

## Render deployment

The root `render.yaml` defines a free demo Blueprint with a web service and PostgreSQL database in Singapore. Push the repository to GitHub, then in Render choose **New > Blueprint** and connect this repository's `main` branch. Review the resources and deploy the Blueprint. It generates `SECRET_KEY`, sets `COOKIE_SECURE=1`, applies migrations and initial grading rules, and provisions the first administrator using the `ADMIN_EMAIL` and `ADMIN_PASSWORD` values Render prompts for. Use a unique admin password of at least 14 characters. After the first deployment succeeds, remove both admin variables from the web service's Environment settings; the administrator account remains in the database.

This free configuration is for a short-lived demo with no real student records. Render free web services spin down after inactivity and have ephemeral filesystems. Free PostgreSQL databases expire after 30 days, have no backups, and are eventually deleted if not upgraded. Use a paid database with backups and a documented retention plan before storing real student records. See Render's [free service limits](https://render.com/docs/free).

The web service checks `/health`; its start command applies database migrations and starts Gunicorn on Render's `PORT`. Review service logs without exposing marks or credentials.

## Data and privacy

Student records remain tied to the authenticated account. Student routes query by the logged-in user's ID and return 404 for other students' assessment IDs. Analytics views omit direct identity fields and expose a randomly assigned reporting key. Marksheets are parsed in memory and the original is discarded; extracted draft rows stay in the private instance folder and expire after 15 minutes, with abandoned draft files removed by `flask cleanup-uploads`. Student data deletion should be carried out under the institution's retention and legal policy, with a database backup before deletion. Use HTTPS in production, a private database network, and least-privilege database roles.

For JPG/PNG OCR on Windows, install Tesseract OCR separately. The app checks `C:\Program Files\Tesseract-OCR\tesseract.exe` by default; set `TESSERACT_CMD` in `.env` if it is installed elsewhere. Scanned PDFs need to be exported as an image for OCR; selectable-text PDFs and spreadsheets do not require Tesseract.

## Current scope and operational limits

The optional `app/prediction.py` module imports scikit-learn only when explicitly called. It requires at least 20 students and 100 historical sequences, validates by held-out students against a mean baseline, and stores evaluation metadata. It saves a model artifact and serves an estimate only if the model beats the baseline and passes the MAE gate. No trained model or result is claimed until the command is run against sufficient real history. Course and semester values are still stored as text/number snapshots rather than foreign keys to normalized Course and Semester tables. Administrators can create/edit student accounts, reset passwords without revealing previous passwords, deactivate accounts, configure versioned grading rules, maintain the subject suggestion catalog, and download aggregate CSV. Profiles allow name and email edits. Power BI `.pbix` is built in Desktop and is not fabricated here. PostgreSQL-specific views still need to be applied and checked against your PostgreSQL instance before importing into Power BI.

For GitHub, initialize the repository and commit the source (keep `.env` ignored), create an empty GitHub repository, add its remote URL, then push the `main` branch. For Render, set a secure `SECRET_KEY`, the managed PostgreSQL `DATABASE_URL`, and `COOKIE_SECURE=1`; no live deployment is included with this source package.
